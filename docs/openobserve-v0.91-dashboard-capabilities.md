# OpenObserve v0.91.0 Dashboard/Query Capability Audit (Stage 16)

Every result below was verified against the real, pinned `public.ecr.aws/zinclabs/openobserve:v0.91.0`
container (`infrastructure/docker/openobserve/Dockerfile`), running inside this repo's own lab
(`pnpm lab:up`), reached only through its loopback-only admin port `http://127.0.0.1:5080` with the
lab's own root Basic Auth credentials — never through the public reverse proxy, never with a
private/undocumented API, and never by reading OpenObserve's source (same methodology as
[`docs/openobserve-v0.91-stream-capabilities.md`](openobserve-v0.91-stream-capabilities.md), Stage
15). Server identity, confirmed via the same unauthenticated `/config` build-info endpoint used
there:

```json
{
  "version": "v0.91.0",
  "build_type": "opensource",
  "commit_hash": "6c610514b4e0d017fb32b798f78d66526f79eb10"
}
```

All write/delete probing below was performed exclusively against disposable, throwaway
folders/dashboards created for this audit (named `chicek-probe-*`/`chicek-dup-*`/`chicek-stable-id-*`)
and deleted again by the end of the session — read-back confirmed zero residue. No canonical stream
(`_rumdata`/`_rumlog`) was written to during this audit.

## Management-plane isolation

Every dashboard/folder/query endpoint above lives under `/api/...` on the loopback-only admin port.
Re-probed live over the browser-facing `https://localhost:8443` reverse proxy with the same admin
Basic Auth header (to isolate reachability from auth):

| Path (via `:8443`)                   | Result |
| ------------------------------------ | ------ |
| `/api/default/dashboards`            | `403`  |
| `/api/v2/default/folders/dashboards` | `403`  |

Both are caught by the reverse proxy's existing, already-verified catch-all `location /api/ { return 403; }`
and the more specific `location ~ ^/(...|dashboards|...)(/|$)` denial
(`infrastructure/docker/reverse-proxy/conf.d/ingestion.conf`, Stage 12) — **no reverse-proxy
configuration change was needed for Stage 16**; every dashboard/folder/query path this stage adds was
already unreachable from the browser-facing surface before this stage existed. Re-verified live by
`scripts/lab/verify-stage16-dashboards.mjs` on every run, the same way Stage 15 re-verifies its own
management-plane isolation.

## Methodology notes

- All folder/dashboard write/delete probing above was performed exclusively against disposable,
  throwaway resources created for this audit (`chicek-probe-*`, `chicek-dup-*`,
  `chicek-stable-id-*`) and deleted again before the end of the session; every deletion was
  confirmed by an independent read-back (`404`/empty list). No canonical stream, no company
  dashboard (none existed at audit time — this is a fresh lab), and no starter dashboard was
  written to or read from during this audit.
- No OpenObserve source code was read; no undocumented/internal header or query parameter was used.
  All requests use the same root Basic Auth the rest of this repo's lab tooling already uses.
- Every `SUPPORTED_AND_VERIFIED`/`SUPPORTED_WITH_LIMITATION` row above has a corresponding automated
  regression in `pnpm test:stage16:dashboards` (`scripts/lab/verify-stage16-dashboards.mjs`), so this
  audit cannot silently drift from the pinned binary's real behavior over time.
- Where this audit could not safely establish real behavior without driving OpenObserve's own web
  UI (dashboard-variable `$name` substitution, #13/#13a; a dashboard panel's own UI time-picker,
  #17), the result is marked `NOT_SAFELY_VERIFIED`/`SUPPORTED_WITH_LIMITATION` rather than assumed,
  and Stage 16's own design (governance doc) avoids depending on the unverified behavior.
